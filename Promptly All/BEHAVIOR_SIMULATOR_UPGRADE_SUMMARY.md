# 行为模拟器升级总结

## 🎯 升级概览

### 升级前 (v2)
```
行为模拟器
    │
    └─→ 云端 API (Render)
         └─→ 云端数据库
```

⚠️ **问题**:
- 云端数据库重置 → 数据丢失
- 需要手动恢复
- 延迟恢复

### 升级后 (v3 - 双向同步)
```
行为模拟器
    ├─→ 本地 SQLite ✅ (确保不丢失)
    │   └─→ 后续可同步到云端
    │
    └─→ 云端 API (Render) ☁️
        └─→ 云端数据库
```

✅ **优势**:
- 本地数据库作为 Source of Truth
- 云端不可用时本地数据仍保存
- 自动同步恢复 (cron job)
- 双重数据保险

## 📊 架构对比

| 方面 | 升级前 | 升级后 |
|------|--------|--------|
| 数据存储位置 | 仅云端 ☁️ | 本地 + 云端 ✅✅ |
| 云端故障影响 | 数据丢失 ❌ | 本地保存 ✅ |
| 故障恢复 | 手动 | 自动 (cron) ✅ |
| 本地数据访问 | 不支持 ❌ | 支持 ✅ |
| API 兼容性 | 完全 ✅ | 完全 ✅ |

## 🔄 数据流对比

### 升级前
```
生成数据 → API 调用 → 云端插入 → 完成/失败
                        ↓ (失败)
                     数据丢失 ❌
```

### 升级后
```
生成数据 → 本地插入 ✅ → API 调用 → 云端插入 → 完成
            ↓ (本地成功)        ↓ (失败)
            保存 ✅             重试 + cron 同步
```

## 🔧 技术细节

### 新增代码

**`get_db_connection()`** (5 行)
```python
def get_db_connection():
    conn = sqlite3.connect(CONFIG["LOCAL_DB_PATH"])
    conn.row_factory = sqlite3.Row
    return conn
```

**`insert_data_to_local_db(users, sessions)`** (90 行)
- 插入用户到 analytics_users
- 插入会话到 analytics_sessions
- 更新日统计表 analytics_daily
- 与云端 API 完全相同的逻辑

### 修改代码

**`api_call_generate_data(users, sessions)`** (改为两步)
1. `insert_data_to_local_db()` - 本地插入
2. 云端 API 调用 - 远程同步
