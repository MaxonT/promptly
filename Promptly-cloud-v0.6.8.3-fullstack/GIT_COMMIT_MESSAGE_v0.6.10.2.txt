fix(i18n): Fix helper functions in specs.js, outcome.js, enhancer.js (v0.6.10.2)

🐛 Fixed Additional i18n Issues in 3 Frontend Files

After v0.6.10.1 fix, comprehensive check revealed 3 more files with 
similar i18n helper function issues.

Problem:
- All 3 files had t() helper functions that returned key names when:
  1. i18n wasn't initialized yet
  2. Translation was missing (i18next fallback behavior)
- Would display technical key names like "specs.untitledSpec" instead 
  of user-friendly text

Root Cause:
```javascript
// Old problematic code in all 3 files
function t(key, options = {}) {
  if (!window.i18n) return key;  // ❌ Returns full key name
  return window.i18n.t(key, options);  // ❌ No validation
}
```

Solution:
1. Use centralized window.i18nManager instead of window.i18n
2. Validate translation result (check if result !== key)
3. Return friendly fallback (key.split('.').pop())
4. Add file-specific console warnings for debugging
