================================================================================
                            核心变化说明
================================================================================

数据库变化:
  • 新表: user_daily_refresh_tracker
    - user_id (TEXT PRIMARY KEY) - 用户ID
    - last_daily_refresh_date (TEXT) - 上次刷新的本地日期 (YYYY-MM-DD)
    - updated_at (TEXT) - 更新时间

刷新逻辑变化:
  旧逻辑: 在固定 UTC 时间 (DAILY_REFRESH_HOUR_UTC) 为所有用户刷新一次
  新逻辑: 每小时检查一次，每个用户在其本地日期变更时刷新

核心函数变化:
  新增:
    - shouldRefreshUserToday(userId, timezone)
    - markUserRefreshedToday(userId, timezone)

  修改:
    - runDailyRefresh() - 改为时区感知
    - startScheduler() - 每小时运行一次
    - forceRefresh() - 清除所有追踪记录

================================================================================
                            使用示例
================================================================================

设置用户时区:
  db.prepare(`UPDATE users SET timezone = ? WHERE id = ?`)
    .run('America/New_York', userId)

查看用户时区:
  SELECT id, email, timezone FROM users;

查看刷新记录:
  SELECT * FROM user_daily_refresh_tracker ORDER BY updated_at DESC;

强制刷新 (测试):
  node -e "import('./src/lib/dailyRefreshJob.js').then(m => 
    console.log(m.forceRefresh()))"

================================================================================
                            关键特性
================================================================================

✅ 时区感知
   • 每个用户有自己的时区和本地日期追踪
   • 支持全球 IANA 标准时区

✅ 公平分配
   • 所有用户在其本地午夜获得日用量
   • 不同时区用户体验一致

✅ 用户友好
   • 用户清楚地了解何时重置用量
   • 可通过设置界面自定义时区

✅ 全球支持
   • 支持 UTC、America/New_York、Asia/Tokyo 等所有时区
   • 无效时区自动回退到 UTC

✅ 向后兼容
   • 现有用户默认时区为 UTC
   • 现有用量记录不受影响
   • 现有订阅系统不变

✅ 数据库无关
   • 同时支持 SQLite 和 PostgreSQL
   • 迁移脚本支持两种数据库

✅ 性能优化
   • 查询已优化，使用索引
   • 每小时检查对性能无显著影响 (<2ms)
